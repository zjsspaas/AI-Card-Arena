# Arena-Backend 功能分析文档

## 📋 项目概述

`arena-backend` 是一个基于 Go 和 Python 的混合后端系统，用于 AI 卡牌竞技场（斗地主游戏）。系统包含游戏引擎、AI Agent 框架、数据库管理等核心功能。

## 🏗️ 项目结构

```
arena-backend/
├── cmd/server/          # 服务器入口（当前为空）
├── config/              # 配置模块
├── Database/            # 数据库初始化
├── engine/              # 游戏引擎（Python）
├── internal/ai-agent/   # AI Agent 框架（Go）
├── model/               # 数据模型
└── main.go              # 主入口（数据库连接测试）

```

## 🔧 核心模块功能

### 1. **数据库配置模块** (`config/database.go`)

**功能：**
- 管理 MySQL 数据库连接
- 配置数据库连接池参数
- 提供全局数据库实例 `DB`

**关键特性：**
- 使用 `github.com/go-sql-driver/mysql` 驱动
- 连接池配置：
  - 最大打开连接数：50
  - 最大空闲连接数：10
  - 连接最大生存时间：1小时
- 数据库：`ddz`（斗地主）
- 用户：`ddz_user`
- 字符集：`utf8mb4`

**使用方式：**
```go
config.InitDB()
// 然后使用 config.DB 进行数据库操作
```

---

### 2. **数据库初始化模块** (`Database/init_db.go`)

**功能：**
- 创建 `ddz` 数据库（如果不存在）
- 设置数据库字符集为 `utf8mb4`
- 用于首次部署时的数据库初始化

**执行方式：**
```bash
go run Database/init_db.go
```

---

### 3. **游戏引擎模块** (`engine/game/engine.py`)

**功能：**
基于 RLCard 框架的斗地主游戏引擎，提供完整的游戏逻辑封装。

**核心类：`GameEngine`**

#### 主要功能：

1. **游戏初始化** (`reset`)
   - 初始化/重置游戏环境
   - 支持设置随机种子
   - 自动发牌、确定地主

2. **状态管理**
   - `get_state(player_id)`: 获取指定玩家的游戏状态
   - `get_perfect_information()`: 获取完整信息（所有玩家手牌）
   - `get_current_player_id()`: 获取当前行动玩家

3. **动作执行** (`step`)
   - 支持动作ID（int）和动作字符串（str）两种格式
   - 自动转换动作格式
   - 执行游戏动作并返回下一步状态

4. **动作映射**
   - `action_id_to_str()`: 动作ID → 字符串（如 "pass", "33", "AAA"）
   - `action_str_to_id()`: 动作字符串 → ID
   - `get_legal_actions()`: 获取合法动作列表

5. **游戏信息查询**
   - `get_landlord_id()`: 获取地主玩家ID
   - `get_hand_cards(player_id)`: 获取玩家手牌（带花色）
   - `get_hand_cards_count(player_id)`: 获取手牌数量
   - `get_all_players_card_count()`: 获取所有玩家手牌数量

6. **游戏状态检查**
   - `is_over()`: 检查游戏是否结束
   - `get_payoffs()`: 获取最终得分（游戏结束后）

7. **资源管理**
   - `cleanup()`: 清理游戏资源

**依赖：**
- `rlcard`: 强化学习卡牌游戏框架
- `numpy`: 数值计算
- `termcolor`: 终端颜色输出

### 4. **AI Agent 框架** (`internal/ai-agent/`)

**功能：**
基于 Gin 框架的可扩展 AI Agent 系统，支持多种类型的 Agent 接入。

#### 4.1 核心接口 (`agent/interface.go`)

**`Agent` 接口定义：**
```go
type Agent interface {
    Name() string                    // Agent 名称
    Description() string             // Agent 描述
    Process(ctx, req) (*Response)   // 处理请求
    Health(ctx) error                // 健康检查
}
```

**请求/响应结构：**
- `Request`: 包含 `message` 和 `params`
- `Response`: 包含 `result`, `status`, `data`, `error`

#### 4.2 Agent 注册器 (`agent/registry.go`)

**功能：**
- 管理所有注册的 Agent
- 线程安全的 Agent 存储和检索
- 支持列出所有 Agent
- 批量健康检查

**主要方法：**
- `Register(agent)`: 注册新 Agent
- `Get(name)`: 根据名称获取 Agent
- `List()`: 列出所有 Agent 信息
- `Health(ctx)`: 检查所有 Agent 健康状态

#### 4.3 内置 Agent 示例

**Echo Agent** (`agent/echo.go`)
- 功能：简单回显，将输入消息原样返回
- 用途：测试和示例

**Calculator Agent** (`agent/calculator.go`)
- 功能：执行基本数学运算（加减乘除）
- 支持格式：`"数字 运算符 数字"`（如 "10 + 5"）

**Chat Agent** (`agent/chat.go`)
- 功能：支持多轮对话的聊天 Agent
- 特性：支持会话管理（通过 `session_id`）

#### 4.4 HTTP 处理器 (`handler/agent_handler.go`)

**功能：**
处理所有 Agent 相关的 HTTP 请求

**主要端点：**
- `ListAgents`: 列出所有可用 Agent
- `ProcessRequest`: 处理 Agent 请求
- `Health`: 检查单个 Agent 健康状态
- `HealthAll`: 检查所有 Agent 健康状态

#### 4.5 路由配置 (`router/router.go`)

**API 路由：**
```
GET  /health                          # 服务健康检查
GET  /api/v1/agents                   # 列出所有 Agent
POST /api/v1/agents/:name/process     # 处理 Agent 请求
GET  /api/v1/agents/:name/health      # 单个 Agent 健康检查
GET  /api/v1/agents/health            # 所有 Agent 健康检查
```

#### 4.6 中间件 (`middleware/`)

**CORS 中间件** (`cors.go`)
- 允许跨域请求
- 支持所有 HTTP 方法
- 允许所有来源（`*`）

**Logger 中间件** (`logger.go`)
- 记录所有 HTTP 请求
- 包含：IP、时间、方法、路径、状态码、延迟、User-Agent

#### 4.7 主程序 (`main.go`)

**功能：**
- 初始化 Agent 注册器
- 注册所有内置 Agent
- 启动 HTTP 服务器（默认端口 8080）
- 配置路由和中间件

**启动方式：**
```bash
cd internal/ai-agent
go run main.go
# 或设置端口
PORT=3000 go run main.go
```

### 5. **数据模型** (`model/user.go`)

**功能：**
定义用户数据模型

**User 结构：**
```go
type User struct {
    ID        uint      // 主键
    Username  string    // 用户名（唯一，最大50字符）
    Password  string    // 密码（最大255字符）
    Role      UserRole  // 角色：admin, developer, viewer
    CreatedAt time.Time // 创建时间
}
```

**用户角色：**
- `Admin`: 管理员
- `Developer`: 开发者
- `Viewer`: 查看者

**注意：** 当前使用 GORM 标签，但数据库配置使用原生 `database/sql`，可能需要调整。

## 🚀 使用流程

### 1. 初始化数据库
```bash
# 创建数据库
go run Database/init_db.go

# 初始化数据库连接配置
# 在应用启动时调用 config.InitDB()
```

### 2. 启动 AI Agent 服务
```bash
cd internal/ai-agent
go run main.go
```

### 3. 使用游戏引擎（Python）
```python
from engine.game.engine import GameEngine

# 创建游戏引擎
engine = GameEngine(seed=42)

# 初始化游戏
state, player_id = engine.reset()

# 获取合法动作
legal_actions = engine.get_legal_actions(player_id)

# 执行动作
next_state, next_player = engine.step("pass")

# 检查游戏是否结束
if engine.is_over():
    payoffs = engine.get_payoffs()
```

### 4. 调用 Agent API
```bash
# 列出所有 Agent
curl http://localhost:8080/api/v1/agents

# 使用 Echo Agent
curl -X POST http://localhost:8080/api/v1/agents/echo/process \
  -H "Content-Type: application/json" \
  -d '{"message": "Hello"}'

# 使用 Calculator Agent
curl -X POST http://localhost:8080/api/v1/agents/calculator/process \
  -H "Content-Type: application/json" \
  -d '{"message": "10 + 5"}'
```

## 📦 技术栈

### Go 语言部分
- **Web 框架**: Gin
- **数据库驱动**: `github.com/go-sql-driver/mysql`
- **ORM**: GORM（在 model 中定义，但未在 config 中使用）
- **Go 版本**: 1.25.4

### Python 部分
- **游戏框架**: RLCard 1.2.0
- **数值计算**: NumPy 2.2.6
- **工具库**: termcolor 3.2.0

## 🔍 待完善的功能

1. **数据库模型集成**
   - `model/user.go` 使用 GORM，但 `config/database.go` 使用原生 SQL
   - 需要统一数据库访问方式

2. **游戏引擎与 Agent 集成**
   - 当前游戏引擎（Python）和 Agent 框架（Go）是分离的
   - 需要建立两者之间的通信机制（可能通过 HTTP API 或进程间通信）

3. **用户认证系统**
   - 定义了 User 模型，但缺少认证中间件
   - 需要实现登录、注册、JWT 等功能

4. **游戏状态持久化**
   - 游戏引擎状态需要保存到数据库
   - 支持游戏回放功能

5. **Agent 与游戏引擎的桥接**
   - 需要创建专门的 Agent 来处理游戏决策
   - 将游戏状态传递给 Agent，Agent 返回动作
